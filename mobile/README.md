# PFT — mobile (React Native / Expo)

The iOS and Android app. It shares the web app's logic layer rather than
reimplementing it, so a figure computed here is the same figure you see in the
browser and in your exports.

## Run it

```bash
cd mobile
npm install
npx expo start          # scan the QR with Expo Go
npm run bundle          # production Android bundle, no device needed
npx expo run:android    # full native build → installable APK
```

## Why this isn't a rewrite

The web app is ~6,600 lines. Roughly 2,100 of them are pure logic — money and
date maths, month statistics, earnings projections, history, export/import,
and the Firestore services. None of that touches the DOM, so it is imported
here untouched:

```
mobile/src/screens/Dashboard.jsx
  └── ../../../src/utils/stats.js      ← the same file the web app uses
  └── ../../../src/hooks/useTransactions.js
  └── ../../../src/context/DataHealthContext.jsx
```

Two pieces of wiring make that possible:

**`mobile/metro.config.js` — `watchFolders`.** Metro only watches its own
project root by default, so it cannot even see the repo's `src/`. The config
adds the repo root, and pins `nodeModulesPaths` to *this* app's
`node_modules` so React resolves to React 19.2.3 (native) instead of
wandering up to the web app's React 19.3.

**`src/firebase/firebase.native.js`.** Metro resolves `./firebase` to
`.native.js` for native bundles and Vite never sees the file, so every service
and hook keeps importing `../firebase/firebase` unchanged. The difference is
auth persistence: the web module calls `setPersistence(browserLocalPersistence)`,
which reads `window` and `localStorage` and would throw on launch in a native
app. The native twin builds auth once with AsyncStorage instead.

The one thing that is *not* shared is `UserContext`. Google sign-in has no
popup in a native app, so it runs an AuthSession flow and hands the ID token to
Firebase via `signInWithCredential`. It reads and writes the same
`users/{uid}/settings/prefs` document, so your currency and preferences follow
you between web and phone.

## Google sign-in setup

Client IDs are per-platform in Google's console, so this must be filled in
once before sign-in works. Until then the button explains exactly what's
missing instead of failing silently.

1. [Google Cloud console](https://console.cloud.google.com/apis/credentials) →
   OAuth client IDs of type **Android** and **iOS** (bundle/package
   `app.pft.tracker`).
2. Put them in `mobile/app.json`:

```json
"extra": {
  "google": {
    "webClientId": "",
    "iosClientId": "",
    "androidClientId": ""
  }
}
```

3. Rebuild the native app (`npx expo run:android`) — the config is baked in at
   build time.

## iOS

`npx expo run:ios` needs **macOS with Xcode**, which this machine does not have
(Windows). The `ios/` directory is generated by `npx expo prebuild` and can be
built on a Mac or in CI (Codemagic, EAS Build, GitHub Actions + macOS runner).
Nothing in the source is Android-specific.
